# 在线发布手册（零基础版）

**这份手册假设你没用过 GitHub、没敲过命令行。** 每一步都写清楚：做什么、在哪做、
成功应该看到什么、看到别的怎么办。

- **总耗时**：第一次约 30–40 分钟，其中一半在等安装和等网页加载
- **花钱吗**：不花。全程用免费额度
- **要会写代码吗**：不要。你只需要复制粘贴几行命令
- **做错了会毁掉数据吗**：不会。所有操作都是「把本地文件复制一份到网上」，
  本地的 Obsidian 笔记不会被改动、不会被删

> 卡住了不要硬试。把报错原文抄下来对照文末的 **[排错大全](#排错大全)**，那里按报错原文分类。

## 一、先看你会得到什么

一个**永久网址**，形如：

```
https://你的用户名.github.io/wind-industry-db/
```

打开是这样三层：

| 打开后看到 | 说明 |
|---|---|
| **首页 = 数据看板** | 六张表切 Tab，能搜索、能筛选、能点列头排序 —— 用起来像 Excel |
| 点项目名 → **详情页** | 那条笔记的完整正文，含「整机采购状态」「待办」 |
| 顶部「笔记详情站」 | 00-总览，统计数字与高价值动态 |

**每天凌晨 02:00 自动更新。** 配好之后你再也不用管它，同事早上打开就是当天数据。

## 二、名词速查（看不懂命令时回来查）

| 名词 | 大白话 |
|---|---|
| **Git** | 装在你电脑上的一个工具，负责把文件夹打包上传、并记住每次改了什么 |
| **GitHub** | 一个网站，用来存 Git 上传的东西。相当于「代码版的百度网盘」 |
| **仓库 / repo** | GitHub 上的一个项目文件夹。我们要建一个叫 `wind-industry-db` 的 |
| **push（推送）** | 把本地改动上传到 GitHub。**这个词后面反复出现** |
| **commit（提交）** | 上传前先给这批改动打个包、写句说明。push 之前必须先 commit |
| **GitHub Actions** | GitHub 提供的免费小机器人。你一 push，它就自动把笔记编译成网页 |
| **GitHub Pages** | GitHub 提供的免费网站托管。Actions 编译完，Pages 负责让别人能访问 |
| **PowerShell** | Windows 自带的命令行窗口。就是那个黑框（或蓝框），敲命令的地方 |
| **公开仓库 / Public** | 任何人都能看到里面的文件。**GitHub Pages 免费版要求仓库必须是 Public** |

**关于「仓库必须公开」的重要提示：**
这意味着**不只是网站公开，仓库里的 Markdown 源文件也公开**。所以下一节必须读。

## 三、⚠️ 哪些内容会被公开（必读）

网站和仓库都是公开的，搜索引擎也会收录。发布前先确认你接受下面这个范围。

| 板块 | 是否发布 | 风险说明 |
|---|---|---|
| 01 每日新闻 | ✅ 发布 | 公开信息整理，无风险 |
| 02 客户与项目 | ✅ 发布 | 项目参数是公开可查的；**但正文的「整机采购状态」「待办」是我方视角** |
| 03 风电政策 | ✅ 发布 | 公开政策，无风险 |
| 04 竞争对手 | ✅ 发布 | **正文含「对我方的含义」** |
| 05 技术方案 | ✅ 发布 | **含我方技术路线判断** |
| 06 投资财务 | ✅ 发布 | 公开财务数据，无风险 |
| 07 战略判断 | ❌ **默认不发布** | 投标策略、失单分析、资源取舍 —— 竞对读到直接受益 |

### 07 是怎么被挡住的

`.github/workflows/deploy.yml` 里已经写好了三重处理，不用你操作：

1. 构建时**不复制** `07-战略判断` 文件夹
2. 把其它笔记里指向 07 的 `[[P0-xxx]]` 链接**降级成纯文字**，站上不会出现死链
3. 删掉总览页里那行指向 07 的导航和统计

本地的 `看板.html`（含 07）已经被 `.gitignore` 挡住，不会被上传。

### 想额外藏某一篇笔记

在那篇笔记最顶上的 YAML 区（两行 `---` 之间）加一行：

```yaml
draft: true
```

网站和看板会**同时**隐藏它，不会出现「表格里有这条、点进去 404」。

### 如果你觉得 02/04/05 的正文也不该公开

有两个选择，按需要选一个：

- **保守做法**：给这些笔记逐篇加 `draft: true`（表格数据仍在，只是点不进详情页）
- **改成私密站**：见[阶段 4](#43-改成只给指定的人看)，换 Cloudflare 托管 + 邮箱白名单

## 阶段 0：准备工作（约 15 分钟）

### 0.1 注册 GitHub 账号

1. 打开 <https://github.com/signup>
2. 依次填邮箱 → 设密码 → 起用户名
   - **用户名会出现在网址里**（`https://用户名.github.io/...`），建议用英文小写，
     比如 `zhenyu-wang`，不要用中文、不要带空格
3. 收邮件填验证码
4. 问你用途/团队规模时随便选，最后**选 Free 免费方案**

✅ **成功标志**：能打开 <https://github.com> 并在右上角看到你的头像。

> 已经有账号就跳过。

---

### 0.2 安装 Git

1. 打开 <https://git-scm.com/download/win>
2. 页面会自动开始下载（如果没有，点 **64-bit Git for Windows Setup**）
3. 双击下载好的 `.exe`，安装过程中**一路点 Next 就行**，不用改任何选项
4. 装完后验证：

   **打开 PowerShell 的方法**：按 `Win 键`，输入 `powershell`，回车。

   在窗口里输入（可以直接复制粘贴，右键即粘贴）：

   ```powershell
   git --version
   ```

✅ **成功标志**：显示类似 `git version 2.47.0.windows.1`。版本号不同没关系。

❌ **如果显示** `无法将"git"项识别为 cmdlet...`：
关掉 PowerShell 重新开一个再试（安装后需要重开窗口才能识别新命令）。还不行就重启电脑。

---

### 0.3 安装 GitHub CLI（强烈建议）

这个工具能让你**用浏览器点一下就完成登录**，不用折磨自己去生成什么 access token。

1. 打开 <https://cli.github.com/>
2. 点 **Download for Windows**，下载 `.msi` 文件
3. 双击安装，一路 Next
4. **关掉 PowerShell，重新开一个**，验证：

   ```powershell
   gh --version
   ```

✅ **成功标志**：显示 `gh version 2.x.x`。

---

### 0.4 告诉 Git 你是谁

Git 每次打包都要记录「谁改的」，所以要先设一下。**把下面两行里的内容换成你自己的**，
一行一行执行：

```powershell
git config --global user.name "Zhenyu"
git config --global user.email "iveryantwang@gmail.com"
```

再执行这一行 —— 它让 Git 正常显示中文文件名（否则你会看到一堆乱码数字，
本手册后面要你「看清楚上传了什么」，没这行就看不懂）：

```powershell
git config --global core.quotepath false
```

✅ **成功标志**：三行都**没有任何输出**。命令行里「没消息就是好消息」。

## 阶段 1：第一次上传（约 10 分钟）

### 1.1 让 PowerShell 进到数据库文件夹

在 PowerShell 里执行（**注意路径两边的双引号不能少**，因为路径里有中文和空格）：

```powershell
cd "D:\works\2026\亚太区工作\风电行业数据库\风电行业数据库"
```

⚠️ **注意**：路径末尾是**两层**同名文件夹，别少写一层。

验证你站对地方了：

```powershell
ls
```

✅ **成功标志**：列出 `00-总览.md`、`01-每日新闻`、`02-客户与项目` …… 一直到 `99-系统`。

❌ **如果报** `找不到路径`：路径打错了。用文件资源管理器打开那个文件夹，
点一下地址栏，路径会变成可复制的文字，复制过来替换双引号里的内容。

---

### 1.2 登录 GitHub

```powershell
gh auth login
```

它会连问几个问题，**用键盘上下箭头选、回车确认**：

| 问题 | 选 |
|---|---|
| What account do you want to log into? | `GitHub.com` |
| What is your preferred protocol...? | `HTTPS` |
| Authenticate Git with your GitHub credentials? | `Yes` |
| How would you like to authenticate? | `Login with a web browser` |

然后它会显示一个**八位验证码**，形如 `A1B2-C3D4`，并提示按回车打开浏览器。

1. **先把这个码抄下来或截图**
2. 按回车，浏览器会自动打开 GitHub 的授权页
3. 把码粘进去 → 点 **Authorize github**

✅ **成功标志**：PowerShell 里出现 `✓ Logged in as 你的用户名`。

---

### 1.3 【重要】先看清楚会上传什么

**这一步不要跳过。** 一旦推到公开仓库，就算之后删掉，
也可能已经被搜索引擎或别人抓走了。

先让 Git 把当前文件夹的所有文件登记一遍：

```powershell
git init
git add -A
```

`git init` 可能会提示 `hint: Using 'master' as the name...` —— 这是正常提醒，忽略。

现在**检查敏感文件有没有被排除掉**：

```powershell
git status --short | Select-String "看板|xlsx|日志|pycache|claudian|obsidian"
```

✅ **成功标志**：**没有任何输出**。说明下面这些都被 `.gitignore` 成功挡住了：

| 被挡住的 | 为什么不能传 |
|---|---|
| `看板.html` | 本地版含 07-战略判断 |
| `*.xlsx` | 每天本地重新生成，没必要占仓库 |
| `99-系统/日志/` | 运行日志，可能含本机路径 |
| `.claudian/` | Claude 插件的会话记录，会累积对话历史 |
| `.obsidian/` | 编辑器配置 + 一个近 3MB 的第三方插件包 |
| `__pycache__/` | Python 缓存 |

❌ **如果有输出**（比如出现 `A  看板.html`）：**先停下**，
说明 `.gitignore` 没生效。执行下面两行重来：

```powershell
git rm -r --cached . -q
git add -A
```

然后重新执行上面的检查命令。

再看一眼一共要传多少文件：

```powershell
git status --short | Measure-Object -Line
```

✅ 正常在 **150 行左右**（140–175 都算正常，笔记增减会浮动）。
如果是**几千行**，说明 `.obsidian` 或缓存混进来了，按上面的方法重来一次。

---

### 1.4 打包并创建仓库

先打包（commit）：

```powershell
git commit -m "init: 风电行业数据库"
git branch -M main
```

✅ **成功标志**：输出以 `[main (root-commit) 一串字母数字] init: 风电行业数据库` 开头，
接着一行 `152 files changed, ...`，然后是一大堆 `create mode 100644 ...`。
文件数不一定正好 152，笔记增减会变。

`git branch -M main` 没有输出，正常。

再用一条命令**建仓库 + 上传**：

```powershell
gh repo create wind-industry-db --public --source=. --remote=origin --push
```

这条命令拆开看就是：建一个叫 `wind-industry-db` 的**公开**仓库，
把当前文件夹关联上去，然后推上去。

✅ **成功标志**：输出
```
✓ Created repository 你的用户名/wind-industry-db on GitHub
✓ Added remote https://github.com/你的用户名/wind-industry-db.git
✓ Pushed commits to https://github.com/你的用户名/wind-industry-db.git
```

---

### 1.5 到网页上确认

打开 <https://github.com>，点右上角头像 → **Your repositories** → 点 `wind-industry-db`。

✅ **成功标志**：能看到 `00-总览.md`、`01-每日新闻` 等文件夹列表。

### ⚠️ 这里有个容易误解的点，务必看懂

你会在仓库里看到 `07-战略判断` 文件夹 —— **这是正常的，不是出错。**

「不发布 07」指的是**不出现在网站上**。但仓库本身是公开的，
所以**源文件仍然能被人翻到**。两者是两回事：

| | 网站（`github.io`） | 仓库（`github.com`） |
|---|---|---|
| 谁会看到 | 你发网址给的人、搜索引擎 | 主动来翻仓库的人 |
| 07 在不在 | ❌ 不在 | ✅ 在（除非你做下面这步） |
| 实际风险 | 低 | 低但不为零 —— 竞对如果知道有这个仓库，能直接读 |

**你有两个选择：**

- **A. 就这样（推荐先这么跑）** —— 07 有云端备份，换电脑不丢。风险是「有人专门来翻你的仓库」，
  概率不高
- **B. 07 完全不上云** —— 看下一小节。代价是 07 只存在你这台电脑上，硬盘坏了就没了

### 1.6 选择 B：让 07 连仓库都不进

**第一步**：用记事本打开数据库文件夹里的 `.gitignore` 文件，在最末尾加一行：

```
07-战略判断/
```

> 找不到 `.gitignore`？它是隐藏文件。在文件资源管理器里点顶部 **查看** →
> 勾选 **隐藏的项目**，就能看到了。

**第二步**：回到 PowerShell 执行：

```powershell
git rm -r --cached "07-战略判断" -q
git add -A
git commit -m "chore: 07-战略判断 不进仓库"
git push
```

✅ **成功标志**：刷新 GitHub 仓库页面，`07-战略判断` 文件夹消失了。

之后 07 只存在你本机 —— Obsidian 照常用、本地 `看板.html` 照常包含它，
只是**没有云端备份了**。

> **建议**：先按 A 跑起来。等整套流程确认顺畅、你也熟悉了操作，再决定要不要收紧到 B。
> 现在就选 B 的话，万一中间出问题，你会分不清是配置错了还是这一步搞的。

## 阶段 2：打开网站（约 5 分钟）

### 2.1 允许 Actions 有发布权限

1. 在仓库页面，点顶部 **Settings**（齿轮图标，在最右边，可能要点 `...` 才看得到）
2. 左侧栏往下拉，找 **Actions** → 点它下面的 **General**
3. 拉到页面最底部 **Workflow permissions**
4. 确认选中 **Read and write permissions** → 点 **Save**

> 多数情况下默认就是对的。这一步是防止后面卡在权限报错。

---

### 2.2 开启 GitHub Pages

1. 还在 **Settings** 里，左侧栏找 **Pages**（在 "Code and automation" 分组下）
2. 中间有个 **Build and deployment** 区块，下面 **Source** 是个下拉框
3. 把它从 `Deploy from a branch` 改成 **`GitHub Actions`**

⚠️ **这是全程最容易点错的一步。** 一定要选 `GitHub Actions`，
不是 `Deploy from a branch`。选错的话网站会是一片空白或 404。

选完**不需要点保存**，它会自动生效。

---

### 2.3 看机器人干活

1. 点仓库顶部的 **Actions** 标签
2. 会看到一条叫 **Deploy Wind DB site** 的记录

| 图标 | 含义 | 怎么办 |
|---|---|---|
| 🟡 黄点（转圈） | 正在构建 | 等 2–4 分钟，刷新页面 |
| ✅ 绿勾 | 成功 | 进入下一步 |
| ❌ 红叉 | 失败 | 点进去看日志，对照[排错大全](#排错大全) |

> 如果 Actions 页面**一条记录都没有**：说明第一次 push 时工作流还没被识别。
> 在 Actions 页面左侧点 `Deploy Wind DB site`，右边会出现
> **Run workflow** 按钮，点它手动跑一次。

---

### 2.4 拿到网址并验收

回到 **Settings → Pages**，页面顶部会出现一个绿色框：

```
Your site is live at https://你的用户名.github.io/wind-industry-db/
```

点 **Visit site**。

**逐项验收**（都通过才算成功）：

- [ ] 首页是**数据看板**，顶部有搜索框和一排 Tab（客户与项目 / 每日新闻 / …）
- [ ] Tab 上有数字，"客户与项目" 应该是 **32**
- [ ] **只有 6 个 Tab，没有「战略判断」** ← 最关键的一项
- [ ] 在搜索框输入 `越南`，Tab 数字变成 5 / 0 / 2 / 2 / 1 / 0
- [ ] 点任意一个项目名，能跳到详情页看到正文
- [ ] 点右上角「📄 笔记详情站」，能打开总览页

❌ **如果首页是一个笔记页面而不是看板**：Actions 里 `Build dashboard` 那步失败了，
点进日志看。

❌ **如果页面没有样式（纯黑白文字堆在一起）**：等 1 分钟刷新。还不行见[排错大全](#排错大全)。

🎉 **全部通过 → 配置完成。把网址发给同事就行。**

## 阶段 3：日常怎么用

### 3.1 每天什么都不用做

`99-系统/scripts/daily_update.bat` 每天 02:00 自动跑完整条链：

```
Claude 检索并写入笔记
  → rebuild_tables.py   重建各索引页表格
  → export_excel.py     导出 Excel（本地用）
  → build_dashboard.py  生成本地看板（含 07，仅本机）
  → git push            上传
  → GitHub Actions      自动重建网站
```

同事早上打开网址就是当天数据。

**确认这个定时任务还在跑**：按 `Win + R`，输入 `taskschd.msc` 回车，
在任务列表里找到它，看「上次运行结果」是不是 `(0x0)`。

---

### 3.2 你手动改了笔记，想马上让网站更新

在 PowerShell 里（先 `cd` 到数据库文件夹）执行这三行：

```powershell
git add -A
git commit -m "更新笔记"
git push
```

引号里的说明可以随便写，比如 `"补充越南项目"`。

然后去仓库的 **Actions** 标签看进度，绿勾后约 1 分钟网站就更新了。

> 嫌麻烦可以合成一行：
> ```powershell
> git add -A; git commit -m "更新"; git push
> ```

---

### 3.3 怎么确认今天的更新上线了

打开网站，看首页标题下面那行小字：

```
数据截至 2026-07-29 · 每日自动更新
```

日期是今天就说明是新的。**如果日期停在几天前**：

1. 先看本地 —— 打开 `99-系统/日志/` 里最新的日志文件，看 bat 有没有报错
2. 再看云端 —— 仓库 Actions 标签里最近一次是不是红叉

### 4.1 换成自己的域名

   → **New repository variable**
   - Name：`SITE_BASEURL`
   - Value：`wind.你公司域名.com`（**不要带 `https://`**）
4. 去 Actions 手动跑一次 **Run workflow**

### 4.2 把 07-战略判断 也发布出去

### 4.3 改成「只给指定的人看」

## 排错大全

### 命令行报错

| 报错原文（关键片段） | 原因 | 怎么办 |
|---|---|---|
| `无法将"git"项识别为 cmdlet` | Git 没装或没重开窗口 | 关掉 PowerShell 重开；还不行就重启电脑 |
| `无法将"gh"项识别为 cmdlet` | GitHub CLI 同上 | 同上 |
| `找不到路径` | `cd` 的路径打错 | 从资源管理器地址栏复制真实路径 |
| `fatal: not a git repository` | 当前不在数据库文件夹里 | 重新执行 [1.1](#11-让-powershell-进到数据库文件夹) 的 `cd` |
| `Author identity unknown` | 没设 user.name / user.email | 回 [0.4](#04-告诉-git-你是谁) |
| `remote origin already exists` | 之前跑过一次 | 执行 `git remote remove origin` 再重试 |
| `Updates were rejected` / `non-fast-forward` | 云端有你本地没有的改动 | 执行 `git pull --rebase origin main` 再 `git push` |
| `nothing to commit, working tree clean` | 没有任何改动 | 不是错误，说明本来就是最新的 |
| `warning: LF will be replaced by CRLF` | 换行符提示 | **无害，忽略** |
| `Permission denied (publickey)` | 登录失效 | 重跑 `gh auth login` |

### 网站问题

| 症状 | 原因 | 怎么办 |
|---|---|---|
| Settings → Pages 里没有绿色网址 | Actions 还没成功跑完 | 去 Actions 看是不是红叉 |
| 打开网址 404 | Source 没选 GitHub Actions | 回 [2.2](#22-开启-github-pages) |
| 首页是笔记不是看板 | `Build dashboard` 步骤失败 | Actions → 点红叉那次 → 点该步骤看日志 |
| 页面没样式，全是黑白文字 | `baseUrl` 与实际域名不符 | 用了自定义域名却没设 `SITE_BASEURL`，见 [4.1](#41-换成自己的域名) |
| 表格是空的 | 笔记 YAML 里 `type` 拼错或缺失 | 检查那篇笔记开头的 `type:` 那一行 |
| 点项目名 404 | 该笔记标了 `draft: true`，或文件名含 `/ \ : * ? " < > \|` | 改文件名，去掉特殊符号 |
| **07 的内容出现在网站上** | `PUBLISH_STRATEGY` 变量被设成了 1 | **立刻**去 Settings → Variables 删掉它，重跑 Actions |
| Actions 红叉，日志里 `npm ci` 失败 | Quartz 上游临时问题 | 等几小时，点 **Re-run all jobs** 重试 |
| Actions 红叉，日志里 `Permission denied` | Actions 权限不足 | 回 [2.1](#21-允许-actions-有发布权限) |

### 看 Actions 日志的方法

1. 仓库 → **Actions** 标签
2. 点最上面那条记录
3. 左边点 **build**
4. 右边是一串折叠的步骤，**红色 ❌ 的那步点开**
5. 往下拉找到红字，那就是真正的报错

看不懂的话：把红字整段复制下来，发给 Claude 让它翻译并给解法。

## 紧急情况：立刻把网站下线

发现不该公开的东西被发出去了，**按顺序做**：

### 第 1 步：让网站立刻不可访问（10 秒）

仓库 → **Settings** → 左侧 **Pages** → **Source** 改回 `Deploy from a branch`
→ 上面的分支下拉框选 `None`。

网站几秒内变 404。

### 第 2 步：让仓库不可访问（30 秒）

仓库 → **Settings** → 拉到最底部 **Danger Zone**
→ **Change repository visibility** → **Make private** → 按提示输入仓库名确认。

### 第 3 步：清理内容

改完笔记后重新推送。注意：**Git 会保留历史记录**，
光删掉文件不够，旧版本仍能被翻出来。彻底清除需要重写历史 —— 这一步找 Claude 帮忙。

### 第 4 步：如果已经被搜索引擎收录

去 <https://search.google.com/search-console> 提交移除请求。
但**别人已经看过、已经存下来的，撤不回来** —— 所以[第三节](#三-哪些内容会被公开必读)才要在发布前读。
