# 每日更新指令（Claude Code 使用）

> 本文件是给 Claude Code 读的作业指令，被 `scripts\daily_update.bat` 引用。
> 内容与 Cowork 定时任务保持一致，改一处记得同步另一处。

**我方身份：风电整机厂（OEM）。** 客户 = 业主/开发商。
核心关注点：**哪些项目的整机尚未定标。**

**竞争对手（`04-竞争对手` 板块）分两类，两类都要查：**

| 类别 | 对象 | 关注重点 |
|---|---|---|
| **中国厂商（重点）** | **金风科技、远景能源、明阳智能、运达股份**、电气风电、三一重能、中车 | **海外订单、出海布局、大兆瓦新机型、海外产能落地** —— 这是与我方直接争夺同一批海外标的的对手 |
| 国际厂商 | Vestas、Siemens Gamesa、Nordex、GE Vernova、Enercon、Suzlon | 订单、产能、本地化投资、财报、人事 |

中国四家（金风/远景/明阳/运达）**每天至少检索一次**，中英文各试。
它们的海外中标一旦发生，往往意味着我方在同一市场的直接失单，须同步在 `02-客户与项目` 把对应项目标记为 `已失单`。

Vault 根目录 = 本文件所在目录的上一级（含 `00-总览.md` 的那一层）。

## 第 2 步：检索 —— 做 14–18 次，每次换关键词

### ⏰ 时间范围：只抓「前一日」

**每次运行只收录前一日发生/发布的信息。** 例如 29 日凌晨运行 → 抓 28 日的信息。

- 检索关键词里带日期时，用**前一日**的日期，不用当天
- 若某条信息实际发布日早于前一日，但**是对库内已有条目的状态更新**（如项目获批、整机定标、失单），仍应收录并按「只增不删」规则更新对应笔记
- 除上述情况外，早于前一日的信息不新建笔记，避免库内堆积旧闻

## 第 3 步：分类写入

| 内容性质 | 文件夹 | type |
|---|---|---|
| 一般行业资讯 | `01-每日新闻` | `news` |
| **具体项目**（有业主、容量、阶段） | `02-客户与项目` | `project` |
| 政策/招标/补贴/审批 | `03-风电政策` | `policy` |
| 竞对整机厂动态 | `04-竞争对手` | `competitor` |
| 机型/基础/运维/混合系统 | `05-技术方案` | `tech` |
| 投资额/IRR/LCOE/PPA/融资 | `06-投资财务` | `finance` |
| 优先级与建议行动 | `07-战略判断` | `strategy` |

### 02-客户与项目（OEM 视角）

- `oem`：已公开就填；**未公开留空** —— 留空即机会
- `opportunity` 必填：
  - `高` — 整机未定 **且** 容量 ≥100MW **且** 阶段在核准/招标中/已中标/环评后期
  - `中` — 整机未定但阶段过早或容量偏小
  - `低` — 已开工且整机大概率锁定，或市场结构上难进
  - `已失单` — 整机已被竞对拿下（同时须在 `04-竞争对手` 建对应记录）
- 正文必须有 `## 整机采购状态`，写明整机是否已定、未定则窗口还有多久
- `## 待办` 写具体动作，不写「持续关注」

**已有同名项目就更新，不新建重复笔记**，并把 `updated` 改为今天。

### 04-竞争对手（中国厂商单列）

- `competitor` 字段用中文名（金风科技 / 远景能源 / 明阳智能 / 运达股份），便于筛选
- 中国厂商的**海外**订单一律标 `importance: 高`，国内订单按容量判断
- 正文须写「**对我方的含义**」：是同一标的的直接失单，还是同区域的先发布局
- 中国厂商拿下我方在库项目时，必须同步把该项目的 `opportunity` 改为 `已失单`（不删原有机会分析）

### 07-战略判断

**越南、意大利、柬埔寨、老挝、哈萨克斯坦五国的判断每天必须复核一遍**，即便当天无新信息，也要确认既有判断的时间窗口是否仍然成立。

每天复核现有判断并增补：

- `P0` — 行动窗口 4 周内关闭（整机定标在即、投标截止临近、已开工但整机未定）
- `P1` — 本月内推动
- `P2` — 持续观察
- `action` 写一句可执行的话，含明确动作与对象
- `rationale` 写优先级依据，关键是**时间窗口**
- 窗口已过的把 `status` 改 `已完成`/`已放弃`，不要删

### 通用要求

- 文件名：项目类 `国别-业主-项目名`，政策类 `国别-政策主题`，竞对类 `公司-事件`，新闻类 `YYYY-MM-DD-标题`
- 不以 `_` 开头，不含 `/ \ : * ? " < > |`
- 加 `publish: true` 与 `created: <今天日期>`
- `source_url` 必须真实可点。**无可靠来源不写入**
- 来源数据冲突时在正文写明分歧，不要取平均
- `importance` 仅 GW 级项目、国家级政策变动、头部厂商重大订单标「高」

### 🔒 尊重人工锁定

**任何笔记 YAML 里有 `manual: true` 的，一律不得修改。**

### 🚫 只增不删 —— 最高优先级规则

**任何情况下都不得删除已有笔记，也不得删除笔记正文中的既有内容。**

新检索到的信息与库内已有信息相关时，一律按「更新」而非「替换」处理：

| 情况 | 正确做法 | 禁止做法 |
|---|---|---|
| 同一项目有新进展（获批/中标/开工/整机定标） | 改 YAML 的 `status`/`oem`/`opportunity` 等字段，并在正文加一段 `**YYYY-MM-DD 更新：**` | 重写正文、删掉旧描述 |
| 发现旧记录的日期或数据有误 | 改字段为正确值，同时在正文写明「此前记为 X，已修正」 | 直接改掉、不留痕 |
| 新来源与旧来源口径冲突 | 两个口径并列写入正文，注明各自来源 | 取平均、或只留新的 |
| 战略判断窗口已过或已解决 | `status` 改 `已完成` / `已放弃` | 删除该笔记 |
| 项目被竞对拿下 | `opportunity` 改 `已失单`，正文保留原先的机会分析 | 删除项目笔记 |
| 发现自己刚建的笔记与已有笔记重复 | **更新已有的那条**，不要新建；若已误建，把内容并入已有笔记后再处理新建的那条 | 删除已有的那条 |

正文里的历史更新段落按时间倒序或顺序累积即可，宁可长，不要丢。库的价值在于能看出**一个项目是怎么一步步走过来的**，删掉旧内容等于毁掉这条时间线。

## 第 5 步：输出简报

stdout 输出中文简报，只讲需要今天做决定的部分：

1. **今日新增**：几条，分布板块
2. **🔴 机会预警**：新发现或状态变化的 `opportunity: 高` 项目，逐条说明整机窗口还有多久
3. **P0 变动**
4. **失单提醒**：竞对拿下了原本标记为机会的项目
